SECTION 01 // SYSTEM ARCHITECTURE

How the Whole Project Works (End-to-End Flow)

Traditional Wireless Sensor Networks (WSNs) send sensor readings to a single centralized server. If an attacker alters a record inside that database (for example, changing a patient or environmental temperature from 24°C to 99°C), a traditional server cannot prove whether the data was modified. Your project solves this using a 4-stage cryptographic blockchain pipeline:

[20 IoT Sensor Nodes (IOT-0 to IOT-19)] │ 1. Senses ambient temperature (15°C – 42°C) + Timestamp ▼ [Mobile Database Node (MDN) Gateway] │ 2. Computes 512-bit SHA-512 Digest: SHA512("node_id temperature") │ Packages record as: "iot_id#temp#timestamp#sha512_hash\n" ▼ [WSNSecurity.sol Ethereum Smart Contract (Port 9545 / Net ID 5777)] │ 3. Calls setIOTData() & addUser() on-chain (Contract: 0x7459...7620) ▼ [Role-Gated Admin Console & Sensor Ledger (Port 5050 / Web UI)] │ 4. Authenticates Admin via getUser() & recomputes SHA-512 on every read └──► Matches = "● SHA-512 VERIFIED" | Altered = "▲ TAMPER BLOCKED"
STAGE 01

Edge Sensing (20 WSN Nodes)

Twenty autonomous sensor nodes (IOT-0 to IOT-19) sample temperature readings across five functional zones and send them to the MDN gateway.

STAGE 02

SHA-512 Cryptographic Seal

The gateway hashes f"{node_id} {sense}" using Python's hashlib.sha512() (or Web Crypto SHA-512 in the browser) to create an unforgeable 128-character hex signature.

STAGE 03

Smart Contract Commit

WSNSecurity.sol stores operator accounts via addUser() and sensor records via setIOTData() on-chain, logging block numbers and commit latency in milliseconds.

STAGE 04

Role-Gated Audit & Verification

Only authenticated operators can unlock the Simulator and Sensor Ledger. On every query, the system re-hashes the temperature to verify 100% data integrity.

WSNStrengthenSecuirty/WSNSimulation.py DESKTOP GUI Standalone Python tkinter desktop window for simulating the 20 WSN nodes and plotting the Transaction Time Graph on your Mac desktop.

SECTION 03 // CUSTOMIZATION CHEAT SHEET

Where to Make Frontend & Backend Changes

1. How to Change Colors or Fonts (Frontend Styling)

Open WSNStrengthenSecuirty/static/templatemo_style.css (lines 3–23) and edit the :root variables:

:root { --bg-cream: #EEF4F3; /* Main page background */ --bg-surface: #F7FBFA; /* Card surface background */ --ink-dark: #0F1C24; /* Primary dark text & node color */ --burgundy: #0D7463; /* Primary accent (buttons, active nodes, chart line) */ --tamper-red: #C81E32; /* Alert red when tamper attack is simulated */ }

2. How to Change Text, Headings, or Credits on the Homepage

Open WSNStrengthenSecuirty/templates/index.html (and root index.html for GitHub Pages):

<!-- Top Header Title --> <span class="brand-name">WSN-CHAIN <span class="slash-accent">//</span> SECURE CLOUD</span> <!-- Big Hero Display Headline --> <span class="hero-line-dark">SECURING IOT</span> <span class="hero-line-burgundy">CLOUD DATA</span>

3. How to Change Sensor Temperature Range or Simulation Speed

• Temperature Range: In WSNStrengthenSecuirty/blockchain_engine.py inside simulate_sensor_reading(), edit sense = random.randint(15, 42).
• Simulation Speed: In WSNStrengthenSecuirty/templates/UserScreen.html inside startWebSimulation(), edit setInterval(..., 1250) (in milliseconds).

4. Remember the Two Frontend Locations

• When running via Python (Run_Project.command on http://127.0.0.1:5050), the server reads from WSNStrengthenSecuirty/templates/*.html and WSNStrengthenSecuirty/static/templatemo_style.css.
• When running via GitHub Pages or without Python, the browser reads the all-in-one file at index.html (and Launch_Dashboard.html) in your main project folder.
